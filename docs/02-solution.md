# 方案与取舍

采用 Python 标准库 CLI，便于无依赖复现。`KnowledgeTools` 从 JSON 文档检索和读取原文。检索使用小规模主题词表，适用于本合成集；文档 ID、版本日期随检索与读取结果返回。`run_agent` 每轮询问模型一个 JSON 动作，执行本地工具，追加可见观察，再询问下一步。`LiveModel` 调用兼容 Chat Completions JSON mode 的端点。`MockModel` 是确定性演示策略，按观察决定读取、补查、回答或停止，不能代表真实模型评测。

模型可选 `search(query)`、`read(doc_id)`、`finish(...)`。Agent 将动作、参数、工具返回、简短行动依据写入 Trace。最终引用必须来自本次已读取文档且是原文连续片段；回答状态必须属于允许集合。有命中文档未读完时不接受 `answered`。模型接口失败、工具失败、步数耗尽均不输出伪造答案。工具失败后由模型观察错误再决定停止；Mock 路径展示这一点。

离线策略对同一主题两个不同原文标记冲突并请求确认。真实模型依系统提示识别语义冲突。原文引用校验只能证明引文存在，不能完全证明回答推论正确，仍需人工或更强的语义评测。另一种方案是接入向量数据库和框架，但四份合成文档不需要其成本；生产场景可更换检索层。
